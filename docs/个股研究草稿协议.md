# 个股研究草稿协议

大模型生成个股研究结果时，第一版使用 JSON 草稿作为中间层。草稿先展示给用户确认，确认后再调用 `import_stock_research_draft` 入库。

草稿生成分两步：

```text
research_provider 收集资料来源
  -> create_research_draft.py 生成草稿骨架
  -> build_research_prompt.py 生成大模型补全 prompt
  -> 大模型或用户补全事实、板块和心得
  -> validate_research_draft.py 校验结构和来源引用
  -> import_stock_research_draft 入库
```

第一版 provider 只负责收集资料来源，不直接声称已经完成事实判断。

## 补全 Prompt

草稿骨架可以转换为补全 prompt：

```bash
python scripts/build_research_prompt.py drafts/000660_KR_research_draft.json
```

输出文件默认与草稿同名，后缀为 `.prompt.md`。该 prompt 约束大模型只输出完整 JSON，不输出解释文字。

## 草稿校验

补全后的草稿入库前需要校验：

```bash
python scripts/validate_research_draft.py examples/sk_hynix_research_draft.json
```

校验内容包括：

- JSON 是否为对象。
- `stock.symbol` 和 `stock.market` 是否存在。
- `sources[].key` 是否唯一。
- `knowledge_items[].source_key` 是否能在 `sources` 中找到。
- `sectors[].path` 是否非空。
- `confidence` 是否在 `0~1`。
- `user_insights[].tags` 是否为字符串数组。

## 一键工作流

可以用一个脚本串起骨架和 prompt 生成：

```bash
python scripts/research_stock.py 000660 KR \
  --manual-source-file examples/manual_sources/sk_hynix_sources.json
```

第一版不会自动调用大模型，只会生成草稿骨架和 prompt，并提示补全、校验、入库命令。

也可以加入公开网页来源：

```bash
python scripts/research_stock.py 000660 KR --name SK海力士 \
  --source-url fact_sheet=https://news.skhynix.com/corporate/fact-sheet/
```

公开网页 provider 会抓取页面标题和正文摘要，写入 `sources[].content_excerpt`，供大模型补全时参考。

## 入库原则

- `stock.symbol` 和 `stock.market` 必填。
- `sources[].key` 只在本次草稿内用于引用，不单独入库。
- `sectors[].path` 表示多级板块树，会逐级创建或复用。
- `confirmed_by_user=true` 时，板块关系和知识项会被标记为用户已确认。
- 第一版不生成 embedding，`embedding` 字段保持为空。
