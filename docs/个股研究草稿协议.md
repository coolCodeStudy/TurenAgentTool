# 个股研究草稿协议

大模型生成个股研究结果时，第一版使用 JSON 草稿作为中间层。草稿先展示给用户确认，确认后再调用 `import_stock_research_draft` 入库。

草稿生成分两步：

```text
research_provider 收集资料来源
  -> create_research_draft.py 生成草稿骨架
  -> build_research_prompt.py 生成大模型补全 prompt
  -> 大模型或用户补全事实、板块和心得
  -> validate_research_draft.py 校验结构和来源引用
  -> import_stock_research_draft 入库
```

第一版 provider 只负责收集资料来源，不直接声称已经完成事实判断。

## 官方源流水线

当前持仓的批量接入使用官方源优先流水线：

```text
富途持仓
  -> OfficialResearchProvider 收集 HKEX / SEC / ETF 发行方来源
  -> source_facts.py 从来源摘录抽取数字和风险片段
  -> Codex research worker 检查资料是否足够
  -> 资料不足时继续发现新来源，并补充 sources/content_excerpt
  -> Codex 补全 research_draft.json
  -> audit.py 校验数字、来源引用和过度推断风险
  -> review_research_draft.py 生成 graph_review.md
  -> import_stock_research_draft 入库
```

官方源 provider 的边界是保守的：

- HK 股票优先尝试 HKEX title search，筛选 `Annual Report`、`Annual Results`、`Interim Results`、`Prospectus` 等公告。
- US 股票优先尝试 SEC company filings，筛选 `10-K`、`20-F`、`10-Q`、`8-K`、`6-K`。
- 已知 ETF 使用发行方页面，例如 iShares、Roundhill、Sprott。
- `--source-url` 仍可作为补充入口，但默认不依赖搜索网站。

自动流水线不会生成 `user_insights`。只有用户明确表达过的观点，才通过心得命令或显式草稿写入。

脚本来源发现不是上限。官方源脚本只提供低成本、可复用、可追溯的第一批材料；Codex research worker 可以继续主动寻找公司 IR、投资者材料、ETF issuer 文档、可靠新闻稿和其他公开资料。每次 Codex 发现脚本没有覆盖的新来源模式，都要写入：

```text
drafts/research_jobs/job_<ID>_<SYMBOL>_<MARKET>/<SYMBOL>_<MARKET>_source_discovery_notes.md
```

该文件用于记录：

- 脚本已找到的来源。
- Codex 额外找到的来源。
- 哪些来源是一次性补充。
- 哪些来源模式值得沉淀成 provider。
- 具体 provider backlog，例如新增 CompanyIRProvider、ETF holdings provider、earnings release parser。

## 补全 Prompt

草稿骨架可以转换为补全 prompt：

```bash
python scripts/build_research_prompt.py drafts/000660_KR_research_draft.json
```

输出文件默认与草稿同名，后缀为 `.prompt.md`。该 prompt 约束大模型只输出完整 JSON，不输出解释文字。

## 草稿校验

补全后的草稿入库前需要校验：

```bash
python scripts/validate_research_draft.py examples/sk_hynix_research_draft.json
```

校验内容包括：

- JSON 是否为对象。
- `stock.symbol` 和 `stock.market` 是否存在。
- `sources[].key` 是否唯一。
- `knowledge_items[].source_key` 是否能在 `sources` 中找到。
- `sectors[].path` 是否非空。
- `confidence` 是否在 `0~1`。
- `user_insights[].tags` 是否为字符串数组。

## 模型补全

第一版模型补全接口是可插拔的：

```bash
python scripts/enrich_research_draft.py drafts/000660_KR_research_draft.json --provider mock
```

`mock` provider 用于验证完整流程，不代表真实研究结论。真实模型 provider 后续接入后，也必须输出同样的 JSON 协议，并通过校验器。

OpenAI provider 只作为显式 fallback。使用前需要在 `.env` 中配置：

```text
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.2
```

## 人工确认

模型补全后的 JSON 不直接入库，先生成审阅稿：

```bash
python scripts/review_research_draft.py examples/sk_hynix_research_draft.json
```

审阅稿包含股票画像、板块归属、事实知识、用户心得、来源和确认后的导入命令。用户确认后再运行：

```bash
python scripts/import_research_draft.py examples/sk_hynix_research_draft.json --confirmed
```

## 一键工作流

可以用一个脚本串起骨架和 prompt 生成：

```bash
python scripts/research_stock.py 000660 KR \
  --manual-source-file examples/manual_sources/sk_hynix_sources.json
```

第一版不会自动调用大模型，只会生成草稿骨架和 prompt，并提示补全、校验、入库命令。

也可以加入公开网页来源：

```bash
python scripts/research_stock.py 000660 KR --name SK海力士 \
  --source-url fact_sheet=https://news.skhynix.com/corporate/fact-sheet/
```

公开网页 provider 会抓取页面标题和正文摘要，写入 `sources[].content_excerpt`，供大模型补全时参考。

也可以优先使用官方源：

```bash
python scripts/create_research_draft.py TLT US --name TLT --official
```

## 来源事实和审核

来源事实抽取：

```bash
python scripts/extract_source_facts.py drafts/LITE_US_research_draft.json
```

审核报告：

```bash
python scripts/audit_research_draft.py drafts/LITE_US_research_draft.json
```

审核状态分三类：

- `pass`：结构校验通过，来源引用存在，明显数字可在来源摘录中追溯。
- `needs_review`：没有硬错误，但存在缺少摘录、非官方来源、数字追溯不足或来源事实不足。
- `fail`：结构错误、`source_key` 不存在，或来源引用无法成立。

只有 `pass`，或用户明确确认的 `needs_review`，才适合自动入库。

## 全持仓批处理

旧同步批处理默认只做官方源抓取和初筛，不再默认调用 OpenAI：

```bash
python scripts/import_portfolio_research.py --auto-confirm-facts
```

如需显式使用 OpenAI fallback：

```bash
python scripts/import_portfolio_research.py --provider openai --auto-confirm-facts --import
```

Codex-first 异步研究队列：

```bash
python scripts/create_research_jobs.py
python scripts/research_agent_worker.py --once
```

`create_research_jobs.py` 会读取当前富途持仓，默认跳过已入库股票，为未入库股票创建 `research_jobs`。`research_agent_worker.py` 会领取一个任务，先跑官方源脚本，再调用 Codex CLI 扩展搜索、补全草稿、写 discovery notes，并在 audit 通过后自动入库。

本地脚本默认会读取仓库 `.env`。如果 `.env` 指向 `localhost:55432` 的本地开发库，`import_research_draft.py`
和 `create_research_jobs.py` 会拒绝写入，避免出现“脚本显示已导入，但 Codex MCP 知识库查不到”的误判。
确实要写本地开发库时，显式传 `--allow-local-db` 或设置 `IKG_ALLOW_LOCAL_DB_WRITE=1`。

可以并行启动多个 worker：

```bash
python scripts/research_agent_worker.py --loop
```

多 worker 通过数据库 `FOR UPDATE SKIP LOCKED` 抢任务，因此可以分布式并发处理。

查看队列：

```bash
python scripts/list_research_jobs.py --status all
```

默认行为：

- 从富途实时持仓读取股票。
- 过滤 `qty <= 0` 的已清仓票。
- 已入库股票默认跳过，除非加 `--refresh`。
- 每只票输出 `research_draft.json`、`source_facts.json`、`audit_report.md`、`graph_review.md`。
- 汇总写入 `drafts/portfolio_research_import_summary.json`。

钉钉/命令入口：

- `研究草稿 09988 HK`：单票生成草稿和审阅，不入库。
- `全持仓研究草稿`：批量生成草稿和审阅，不入库。
- `持仓图谱补全`：批量导入审核通过的草稿，属于写入类命令，只允许白名单用户触发。

## 入库原则

- `stock.symbol` 和 `stock.market` 必填。
- `sources[].key` 只在本次草稿内用于引用，不单独入库。
- `sectors[].path` 表示多级板块树，会逐级创建或复用。
- `confirmed_by_user=true` 时，板块关系和知识项会被标记为用户已确认。
- 第一版不生成 embedding，`embedding` 字段保持为空。
