# MVP 路线图

## 阶段 0：需求固化

目标：把想法沉淀为可实现的边界。

产出：

- 技术方案。
- 数据模型。
- 数据库 schema。
- MCP 工具清单。

当前状态：已完成。

## 阶段 1：知识库基础能力

目标：先能录入、查询、更新。

任务：

1. 搭建 PostgreSQL schema。
2. 实现 InvestmentKnowledge MCP Server。
3. 实现股票画像 upsert。
4. 实现板块树 upsert。
5. 实现用户心得写入。
6. 实现基础查询。

验收标准：

- 输入股票后，可以保存股票画像。
- 股票能挂到多级板块。
- 用户心得能保存并按股票/板块查回。

当前状态：已完成第一版基础闭环。

已实现：

- Python + FastMCP 工程骨架。
- PostgreSQL + pgvector Docker Compose。
- 数据库初始化脚本。
- 股票画像、板块树、股票板块关系、知识项、用户心得的写入和查询。
- 本地 smoke test。

## 阶段 2：个股学习流程

目标：让大模型成为研究员，但入库由用户确认。

任务：

1. 设计个股研究 prompt。
2. 接入外部搜索或资料查询工具。
3. 输出候选股票画像。
4. 用户确认后写入数据库。
5. 对来源、置信度、确认状态做完整记录。

验收标准：

- 用户输入股票代码后，系统能生成结构化画像。
- 用户可以确认、修改或拒绝。
- 入库后能再次查询并引用历史内容。

当前状态：已启动。

已实现：

- 个股研究草稿 JSON 协议。
- 用户确认后的草稿导入工具。
- 样例草稿和本地导入脚本。

## 阶段 3：持仓复盘

目标：围绕真实持仓生成每日复盘。

任务：

1. 接入 Futu MCP 获取持仓。
2. 同步 positions。
3. 接入同花顺 MCP 获取公告、新闻、板块近况。
4. 生成每日复盘报告。
5. 将重要变化写入待确认知识。

验收标准：

- 能看到当前持仓结构。
- 能按持仓拉相关公告和板块变化。
- 能生成一份可读的每日复盘。

## 阶段 4：自学习闭环

目标：让系统真正越用越懂用户。

任务：

1. 用户心得自动结构化。
2. 分析股票/板块时自动检索相关历史心得。
3. 复盘时检查历史判断是否被验证。
4. 对被验证或被证伪的判断做标记。
5. 沉淀用户偏好画像。

验收标准：

- 用户问某只股票时，系统能引用过去说过的相关心得。
- 系统能指出“这个结论和你之前的判断有冲突”。
- 系统能逐步形成用户偏好标签。

## 阶段 5：云端服务化

目标：让系统脱离个人 Mac，成为可长期运行的远端服务。

任务：

1. 将 PostgreSQL + pgvector 部署到阿里云 ECS 或托管 PostgreSQL。
2. 将 InvestmentKnowledge MCP Server 部署到云端。
3. 抽象 `research_providers`，支持官方网页、搜索、Futu MCP、同花顺 MCP。
4. 建立资料查询到研究草稿的流水线。
5. 增加定时任务，支持每日复盘和知识复核。

验收标准：

- 个人 Mac 关机后，数据库和定时任务仍可运行。
- ChatGPT、Codex 或其他客户端可以调用同一个远端 MCP Server。
- 输入股票后，系统能由云端 provider 查询资料并生成待确认研究草稿。
- 用户确认后，研究草稿能写入云端知识库。
