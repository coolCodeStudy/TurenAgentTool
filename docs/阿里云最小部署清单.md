# 阿里云最小部署清单

这份清单用于第一次把 InvestmentKnowledge 部署到 ECS。目标是先跑通最小闭环：ECS 上的 Postgres/pgvector、OpenAI 分析、钉钉 Stream Mode 长连接机器人。

## 1. ECS 准备

- 系统：Ubuntu 22.04 LTS。
- 规格：2 vCPU / 4GB RAM 起步。
- 磁盘：40GB ESSD 起步。
- 安全组第一版只开放：
  - SSH：`22`，限制为你的固定 IP 更好。
- 如果只用钉钉 Stream Mode，`8000`、`8001`、`8002` 可以先不开放公网。
- 如果需要临时验证 HTTP 入口，再把 `8000`、`8001`、`8002` 只对你的固定 IP 开放。
- PostgreSQL 端口不要开放公网。

## 2. 服务器软件

在 ECS 上安装：

- Docker Engine
- Docker Compose plugin

安装命令以 [DEPLOYMENT.md](../DEPLOYMENT.md) 为准。
GitHub Actions 部署流也会尝试自动安装这些基础依赖；手工安装仍然更可控，自动安装适合第一次快速跑通。
代码和 Docker 镜像会由 GitHub Actions 通过 SCP 上传，ECS 不需要能访问 GitHub 或 Docker Hub。

## 3. 代码和配置

```bash
sudo mkdir -p /opt/investment-knowledge
sudo chown -R "$USER":"$USER" /opt/investment-knowledge
git clone <your-repo-url> /opt/investment-knowledge
cd /opt/investment-knowledge
python scripts/generate_prod_env.py --output .env
```

编辑 `.env`，至少确认：

- `POSTGRES_PASSWORD` 是强密码。
- `COMMAND_API_TOKEN` 是强 token。
- `OPENAI_API_KEY` 如果暂时不用模型补全，可以先为空。
- `DINGTALK_STREAM_CLIENT_ID` 和 `DINGTALK_STREAM_CLIENT_SECRET` 用于钉钉 Stream Bot。
- `COMPOSE_PROFILES=stream` 用于启用 Stream Bot 容器。
- `COMPOSE_PROFILES=stream` 第一版只启动 `postgres` 和 `dingtalk-stream-bot`；以后需要 HTTP/MCP 入口再改成 `stream,http`。
- `DINGTALK_OUTGOING_SECRET` 如果暂时不接普通 outgoing webhook，可以先为空。
- `DINGTALK_ALLOW_WRITE_COMMANDS=false` 保持默认。
- `DINGTALK_STREAM_ALLOW_WRITE=false` 保持默认。
- `PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/` 可加速服务器上的 Python 镜像构建。

## 4. 启动和自检

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
COMMAND_API_TOKEN=$(grep '^COMMAND_API_TOKEN=' .env | cut -d= -f2-) python scripts/prod_check.py
```

预期结果：

- `mcp endpoint` 返回 HTTP `406` 也算正常，表示 HTTP 路由可达但普通 curl 不是 MCP 客户端。
- `command unauthorized` 返回 HTTP `401`。
- `dingtalk write guard` 通过，表示钉钉入口默认不会确认候选或记录心得。

## 5. 最小验证命令

```bash
curl -i http://localhost:8001/health
curl -i http://localhost:8002/health
curl -s http://localhost:8001/command \
  -H "Authorization: Bearer $(grep '^COMMAND_API_TOKEN=' .env | cut -d= -f2-)" \
  -H "Content-Type: application/json" \
  -d '{"text":"帮助","sender":"deploy-check","source":"curl"}'
```

导入海力士数据后再验证：

```bash
COMMAND_API_TOKEN=$(grep '^COMMAND_API_TOKEN=' .env | cut -d= -f2-) \
  python scripts/prod_check.py --analysis-command "怎么看海力士"
```

## 6. 钉钉 Stream Bot 验证

```bash
docker compose -f docker-compose.prod.yml logs -f dingtalk-stream-bot
```

看到 `DingTalk Stream bot starting` 后，在钉钉群里 `@机器人 怎么看海力士`。如果收到分析回复，说明上班时也能通过钉钉和系统沟通。

## 7. GitHub Actions 自动部署

ReportingSystem 的上云方式是 GitHub Actions 通过 SSH 到 ECS 重启服务。本项目已采用同一个思路，但部署的是 Docker Compose。

在 `coolCodeStudy/TurenAgentTool` 仓库配置这些 GitHub Secrets：

- `ECS_HOST`
- `ECS_USERNAME`
- `ECS_PASSWORD`
- `ECS_PORT`，如果 SSH 不是默认 `22` 才需要
- `POSTGRES_PASSWORD`
- `COMMAND_API_TOKEN`
- `OPENAI_API_KEY`
- `DINGTALK_STREAM_CLIENT_ID`
- `DINGTALK_STREAM_CLIENT_SECRET`

可选：

- `DINGTALK_OUTGOING_SECRET`
- `DINGTALK_SEND_WEBHOOK`
- `DINGTALK_SEND_SECRET`

配置完成后，可以手动触发 `Deploy to Alibaba Cloud ECS` workflow，或者 push 到 `main` 自动部署。

## 8. 普通 webhook 机器人接入前

真实接入钉钉前需要：

- 给服务加 HTTPS。
- 配置 `DINGTALK_OUTGOING_SECRET`。
- 钉钉 outgoing 机器人回调地址指向 `/dingtalk/webhook`。
- 安全组不要长期裸露 `8001`、`8002` 给公网。

Stream Mode 不需要这几项，可以先跳过。

## 9. 暂缓事项

这些不阻塞第一次部署：

- 真实域名和反向代理。
- HTTPS 自动证书。
- Futu MCP / 同花顺 MCP。
- 每日持仓复盘。
- 生产数据库备份自动化。
