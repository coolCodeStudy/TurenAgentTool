# Change Tasks

## Checklist

- [ ] Product scope or operating-model scope is clear.
- [ ] Technical or process design is clear.
- [ ] Implementation or document changes are complete.
- [ ] Verification is complete.
- [ ] Delivery state is updated.
- [ ] Acceptance state is updated or marked `not_required` with reason.
- [ ] Lessons are recorded or `Lessons: none` is stated with reason.
- [ ] Change is folded back into current truth or explicitly left active.
