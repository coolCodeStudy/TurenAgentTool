# 消息入口设计

## 目标

消息入口负责把外部消息转成 InvestmentKnowledge 的统一指令。第一版不要让外部机器人直接操作数据库，而是统一调用 `investment_knowledge_mcp.command_router.handle_command()`。

```text
钉钉 / Web API / Hermes / OpenClaw
  -> auth + allowlist
  -> command_router.handle_command()
    -> repository / MCP tools
      -> PostgreSQL
```

## 入口选择

### 第一选择：轻量 Web API

适合部署到阿里云 ECS。自己实现一个很薄的 HTTP 服务，例如 `/command`：

```json
{
  "text": "分析 000660 KR",
  "sender": "user-id",
  "source": "dingtalk"
}
```

优点：

- 权限和日志最好控制。
- 可以复用同一个 `command_router`。
- 后续钉钉、网页、其他 agent 都可以接进来。

### 钉钉机器人

适合日常使用。建议只作为消息入口，不直接承担业务逻辑。

推荐支持的指令：

```text
分析 000660 KR
查看候选心得
确认候选心得 6
拒绝候选心得 5
记录心得 000660 KR 这里写你的正式心得
提出个股候选心得 000660 KR 这里写系统推断出的候选心得
```

安全建议：

- 只允许指定群或指定用户。
- 写入类指令必须记录审计日志。
- `record_user_insight` 只用于用户明确说出的观点。
- 系统推断只能走 `propose_candidate_insight`。
- 高风险指令，例如删除、批量确认、导入研究草稿，第一版不要开放给群聊。

已新增第一版 adapter：`investment_knowledge_mcp.dingtalk_api`。

- 入口：`POST /dingtalk/webhook`
- 健康检查：`GET /health`
- 支持钉钉文本消息 `text.content`，也兼容语音识别文本 `content.recognition`
- 默认只允许查询类指令：`分析 000660 KR`、`查看候选心得`、`帮助`
- 设置 `DINGTALK_OUTGOING_SECRET` 后会校验钉钉回调里的 `timestamp` 和 `sign`
- 所有执行过的指令都会写入 `command_events`，`source=dingtalk`

另有发送侧自定义机器人：

- `DINGTALK_SEND_WEBHOOK`：钉钉自定义机器人发送消息 webhook。
- `DINGTALK_SEND_SECRET`：发送侧加签 secret。
- `scripts/send_dingtalk_message.py --message "..."`：发送普通文本。
- `scripts/send_dingtalk_message.py --command "怎么看海力士"`：执行统一指令并把结果推送到群。

### 钉钉 Stream 模式

Stream 模式适合“用户在钉钉里发消息，程序收到后回复”。它不需要公网 HTTPS，程序会主动与钉钉建立长连接。

- 配置：`DINGTALK_STREAM_CLIENT_ID`、`DINGTALK_STREAM_CLIENT_SECRET`
- 启动：`scripts/dingtalk_stream_bot.py`
- 默认只允许查询类指令。
- 写入类指令仍需显式加 `--allow-write`，第一版不建议在群聊开启。

### Hermes / OpenClaw / 其他 Agent 外壳

可以作为更复杂的 agent 编排层，但第一版不建议让它们直接拥有数据库写权限。

推荐边界：

- Agent 外壳负责理解自然语言和调度。
- InvestmentKnowledge 负责数据边界、确认逻辑和持久化。
- 所有写入都走 `command_router` 或 MCP 工具，不绕过候选确认机制。

## 指令风险分层

| 风险级别 | 指令 | 处理方式 |
| --- | --- | --- |
| 低 | `分析 000660 KR`、`查看候选心得` | 可直接执行 |
| 中 | `提出个股候选心得 ...` | 可执行，但只进入候选区 |
| 高 | `记录心得 ...`、`确认候选心得 6` | 需要确认用户身份并记录审计 |
| 暂不开放 | 删除数据、批量确认、直接导入研究草稿 | 只保留本地/管理员入口 |

## 第一版 Web API

已新增独立服务 `investment_knowledge_mcp.command_api`，不和 MCP endpoint 混在一起：

```text
POST /command
Authorization: Bearer <COMMAND_API_TOKEN>
```

请求：

```json
{
  "text": "分析 000660 KR",
  "sender": "lishaocheng",
  "source": "dingtalk"
}
```

响应：

```json
{
  "ok": true,
  "message": "已生成 SK海力士 分析上下文：drafts/000660_KR_analysis_context.md"
}
```

健康检查：

```text
GET /health
```

本地运行示例：

```bash
COMMAND_API_TOKEN=dev-token .venv/bin/python -m investment_knowledge_mcp.command_api
curl -s http://localhost:8001/command \
  -H "Authorization: Bearer dev-token" \
  -H "Content-Type: application/json" \
  -d '{"text":"查看候选心得","sender":"local","source":"curl"}'
```

所有 `/command` 调用都会写入 `command_events` 审计表。

## 上云前最低要求

- 设置 `COMMAND_API_TOKEN`。
- 如果启用钉钉入口，设置 `DINGTALK_OUTGOING_SECRET`。
- 只暴露 HTTPS，不裸奔 HTTP。
- 安全组只开放 80/443，PostgreSQL 不开放公网。
- 保留 `/mcp`、`/command` 和 `/dingtalk/webhook` 的访问日志。
- 数据库每日备份。
- 写入类指令记录 sender、source、command、result、created_at。

## 后续扩展

1. 给 `command_router` 增加 structured command 返回值，方便机器人渲染卡片。
2. 增加钉钉用户 allowlist。
3. 将钉钉查询结果渲染成 Markdown 或互动卡片。
4. 增加“确认候选心得”的交互按钮。
5. 增加“每日复盘”定时推送。
