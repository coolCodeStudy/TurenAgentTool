# 当前工程状态

## 当前定位

InvestmentKnowledge MCP 当前是一个投资知识图谱系统的第一版后端骨架。它的重点不是自动交易，而是把个股研究、板块归类、事实知识、用户心得和后续复盘沉淀成可查询、可确认、可追溯的知识库。

个人 Mac 是开发环境和交互入口，不是长期运行环境。长期目标是部署到阿里云 ECS 或其他云端环境。

### 数据库和 MCP

- 使用 PostgreSQL + pgvector。
- 本地开发数据库通过 Docker Compose 启动。
- 宿主机端口为 `55432`，避免与 ReportSystem 的 PostgreSQL `5432` 冲突。
- MCP Server 使用 Python + FastMCP。
- 本地默认 `stdio` transport，云端使用 `streamable-http`。

### 个股研究链路

当前链路已经可以完整跑通：

```text
资料来源
  -> 生成研究草稿骨架
  -> 生成模型 prompt
  -> 模型补全 enriched draft
  -> 校验 JSON 和来源引用
  -> 生成人工审阅稿
  -> 用户确认
  -> confirmed 入库
```

已支持：

- 手工资料来源 provider。
- 公开网页抓取 provider。
- OpenAI Responses API provider。
- mock provider，用于不花钱跑通流程。
- 草稿校验器。
- 人工审阅稿生成器。

### 分析上下文与用户记忆

已实现第一版分析上下文层：

```text
个股/板块
  -> 股票画像和板块路径
  -> 事实知识和来源
  -> 个股心得
  -> 板块心得
  -> portfolio / strategy 级用户偏好
  -> 待确认候选心得
  -> Markdown 分析上下文
```

已支持：

- `get_stock_context`：构建个股分析上下文。
- `get_sector_context`：构建板块分析上下文。
- `record_user_insight`：按股票代码、板块路径或全局类型写入用户心得。
- `propose_candidate_insight`：写入系统推断出的待确认候选心得。
- `confirm_candidate_insight` / `reject_candidate_insight`：把候选心得转正或拒绝。
- `scripts/build_analysis_context.py`：导出可读 Markdown context。
- OpenAI 分析 provider：配置 `OPENAI_API_KEY` 后，分析类指令会优先基于 context 调 OpenAI 生成研究员风格分析；未配置或失败时回退到本地模板分析。

### 统一指令入口

已实现统一指令入口：

```bash
python scripts/ikg.py "分析 000660 KR"
python scripts/ikg.py "怎么看海力士"
python scripts/ikg.py "分析一下腾讯"
python scripts/ikg.py "查看候选心得"
python scripts/ikg.py "确认候选心得 6"
python scripts/ikg.py "拒绝候选心得 5"
python scripts/ikg.py "记录心得 000660 KR 这里写你的正式心得"
python scripts/ikg.py "提出个股候选心得 000660 KR 这里写系统推断出的候选心得"
```

`investment_knowledge_mcp.command_router` 是钉钉机器人、Web API、Hermes/OpenClaw 外壳可复用的指令解析层。它已支持：

- 严格命令，例如 `分析 000660 KR`。
- 自然问法，例如 `怎么看海力士`。
- 按股票名称解析入库股票，例如 `海力士` -> `000660 KR`。
- 直接返回简短分析，同时继续生成 Markdown 分析上下文文件。

### 消息入口

已实现第一版消息入口：

- `investment_knowledge_mcp.command_api`：通用 HTTP `/command`，带 token 鉴权和审计。
- `investment_knowledge_mcp.dingtalk_api`：钉钉 outgoing webhook adapter，默认只开放查询类指令。
- `command_events`：记录消息入口触发的指令、来源、发送者和结果。
