# 当前工程状态

## 当前定位

InvestmentKnowledge MCP 当前是一个投资知识图谱系统的第一版后端骨架。它的重点不是自动交易，而是把个股研究、板块归类、事实知识、用户心得和后续复盘沉淀成可查询、可确认、可追溯的知识库。

个人 Mac 是开发环境和交互入口，不是长期运行环境。长期目标是部署到阿里云 ECS 或其他云端环境。

- 使用 PostgreSQL + pgvector。
- 本地开发数据库通过 Docker Compose 启动。
- 宿主机端口为 `55432`，避免与 ReportSystem 的 PostgreSQL `5432` 冲突。
- Environment reality check on 2026-07-01: the active local `turenagenttool_prod-postgres-1` container was mapped to `127.0.0.1:55433`, while `127.0.0.1:55432` was not reachable from the coordinator worktree. Treat the documented `55432` value as the standard target, not proof that the database is currently running there.
- MCP Server 使用 Python + FastMCP。
- 本地默认 `stdio` transport，云端使用 `streamable-http`。

### 个股研究链路

当前链路已经可以完整跑通：

```text
资料来源
  -> 生成研究草稿骨架
  -> 生成模型 prompt
  -> 模型补全 enriched draft
  -> 校验 JSON 和来源引用
  -> 生成人工审阅稿
  -> 用户确认
  -> confirmed 入库
```

已支持：

- 手工资料来源 provider。
- 公开网页抓取 provider。
- OpenAI Responses API provider。
- mock provider，用于不花钱跑通流程。
- 草稿校验器。
- 人工审阅稿生成器。

### 分析上下文与用户记忆

已实现第一版分析上下文层：

```text
个股/板块
  -> 股票画像和板块路径
  -> 事实知识和来源
  -> 个股心得
  -> 板块心得
  -> portfolio / strategy 级用户偏好
  -> 待确认候选心得
  -> Markdown 分析上下文
```

已支持：

- `get_stock_context`：构建个股分析上下文。
- `get_sector_context`：构建板块分析上下文。
- `record_user_insight`：按股票代码、板块路径或全局类型写入用户心得。
- `propose_candidate_insight`：写入系统推断出的待确认候选心得。
- `confirm_candidate_insight` / `reject_candidate_insight`：把候选心得转正或拒绝。
- `scripts/build_analysis_context.py`：导出可读 Markdown context。
- OpenAI 分析 provider：配置 `OPENAI_API_KEY` 后，分析类指令会优先基于 context 调 OpenAI 生成研究员风格分析；未配置或失败时回退到本地模板分析。

### 统一指令入口

已实现统一指令入口：

```bash
python scripts/ikg.py "分析 000660 KR"
python scripts/ikg.py "怎么看海力士"
python scripts/ikg.py "分析一下腾讯"
python scripts/ikg.py "查看候选心得"
python scripts/ikg.py "确认候选心得 6"
python scripts/ikg.py "拒绝候选心得 5"
python scripts/ikg.py "记录心得 000660 KR 这里写你的正式心得"
python scripts/ikg.py "提出个股候选心得 000660 KR 这里写系统推断出的候选心得"
```

`investment_knowledge_mcp.command_router` 是钉钉机器人、Web API 和受控 agent shell 可复用的指令解析层。它已支持：

- 严格命令，例如 `分析 000660 KR`。
- 自然问法，例如 `怎么看海力士`。
- 按股票名称解析入库股票，例如 `海力士` -> `000660 KR`。
- 直接返回简短分析，同时继续生成 Markdown 分析上下文文件。
- 默认个股查看已分层：`分析 SYMBOL MARKET` 返回 Level 1 决策卡片，`分析详情 SYMBOL MARKET` 保留完整分析路径。

### 部署分层

- Full deploy：用于 `Dockerfile`、`requirements.txt`、`docker-compose.prod.yml`、依赖或镜像结构变化；会重建并上传镜像，耗时较长。
- Quick deploy：用于 `investment_knowledge_mcp/`、`scripts/*.py`、`db/`、文档和 shell 脚本等日常迭代；只同步代码并重启部分后台服务，不重建镜像。当前 GitHub Actions quick deploy 没有覆盖 `weekly-review-web`，周复盘 Web 修复需要 full deploy 或先补 quick deploy 范围。
- 生产容器通过 volume 挂载宿主机代码目录，镜像主要承载 Python 依赖和运行环境。

### Kline Agent V1 acceptance environment

- Kline Agent V1 live acceptance needs more than the deterministic fixture tests: it needs a Python environment with `futu-api`, a reachable Futu OpenD historical K-line source, and a command path that can run without being blocked by database bootstrap.
- On 2026-07-01, the coordinator environment had no `.venv/bin/python`; the main repo virtualenv had `psycopg` but not `futu-api`; `127.0.0.1:55432` was not reachable; Docker showed the active local project Postgres mapped to `127.0.0.1:55433`; and the visible Futu process was the FutuNiuniu app, not a verified OpenD gateway.
- Coordinator follow-up on 2026-07-01 created the task-worktree virtualenv, installed `requirements.txt` including `futu-api`, confirmed the active local command DB is reachable as `127.0.0.1:55433`, and verified `scripts/ikg.py` can run the Kline command with `POSTGRES_PORT=55433 FUTU_OPEND_PORT=11111`.
- Historical 2026-07-01 environment finding: `/Applications/Futu_OpenD.app` launched and local config said API port `11111`, but no listener was active on `127.0.0.1:11111` or `11112`; `scripts/ikg.py "K线调查 US.NVDA 5年 前复权"` returned an honest provider limitation instead of hanging.
- User clarified on 2026-07-03 that local FutuD/OpenD must never be used and has been deleted locally. Future local Kline acceptance must not try to install, launch, or depend on FutuD/OpenD.
- Local review can accept only the fixture/degraded-provider V1 behavior with `KLINE_PROVIDER=disabled`: read-only output, deterministic fixture statistics, no direct trading advice, and honest provider-unavailable or insufficient-evidence messaging. Full live K-line acceptance requires a non-Futu provider path or an approved remote provider environment.
- User browser check on 2026-07-04 found that `/command` Preview returned `Unrecognized` for `K线调查 US.NVDA 5年 前复权` because Command Workbench had not registered Kline as a website action.
