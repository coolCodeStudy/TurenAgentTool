# 当前工程状态

## 当前定位

InvestmentKnowledge MCP 当前是一个投资知识图谱系统的第一版后端骨架。它的重点不是自动交易，而是把个股研究、板块归类、事实知识、用户心得和后续复盘沉淀成可查询、可确认、可追溯的知识库。

个人 Mac 是开发环境和交互入口，不是长期运行环境。长期目标是部署到阿里云 ECS 或其他云端环境。

- 本地开发数据库通过 Docker Compose 启动。

- 本地默认 `stdio` transport，云端使用 `streamable-http`。

### 个股研究链路

当前链路已经可以完整跑通：

```text
资料来源
  -> 生成研究草稿骨架
  -> 生成模型 prompt
  -> 模型补全 enriched draft
  -> 校验 JSON 和来源引用
  -> 生成人工审阅稿
  -> 用户确认
  -> confirmed 入库
```

已支持：

- OpenAI Responses API provider。
- mock provider，用于不花钱跑通流程。
- 草稿校验器。
- 人工审阅稿生成器。

### 分析上下文与用户记忆

已实现第一版分析上下文层：

```text
个股/板块
  -> 股票画像和板块路径
  -> 事实知识和来源
  -> 个股心得
  -> 板块心得
  -> portfolio / strategy 级用户偏好
  -> 待确认候选心得
  -> Markdown 分析上下文
```

已支持：

- `get_stock_context`：构建个股分析上下文。
- `get_sector_context`：构建板块分析上下文。
- `record_user_insight`：按股票代码、板块路径或全局类型写入用户心得。
- `propose_candidate_insight`：写入系统推断出的待确认候选心得。
- `confirm_candidate_insight` / `reject_candidate_insight`：把候选心得转正或拒绝。
- `scripts/build_analysis_context.py`：导出可读 Markdown context。
- OpenAI 分析 provider：配置 `OPENAI_API_KEY` 后，分析类指令会优先基于 context 调 OpenAI 生成研究员风格分析；未配置或失败时回退到本地模板分析。

### 统一指令入口

已实现统一指令入口：

```bash
python scripts/ikg.py "分析 000660 KR"
python scripts/ikg.py "怎么看海力士"
python scripts/ikg.py "分析一下腾讯"
python scripts/ikg.py "查看候选心得"
python scripts/ikg.py "确认候选心得 6"
python scripts/ikg.py "拒绝候选心得 5"
python scripts/ikg.py "记录心得 000660 KR 这里写你的正式心得"
python scripts/ikg.py "提出个股候选心得 000660 KR 这里写系统推断出的候选心得"
```

`investment_knowledge_mcp.command_router` 是钉钉机器人、Web API 和受控 agent shell 可复用的指令解析层。它已支持：

- 严格命令，例如 `分析 000660 KR`。
- 自然问法，例如 `怎么看海力士`。
- 按股票名称解析入库股票，例如 `海力士` -> `000660 KR`。
- 直接返回简短分析，同时继续生成 Markdown 分析上下文文件。
- 默认个股查看已分层：`分析 SYMBOL MARKET` 返回 Level 1 决策卡片，`分析详情 SYMBOL MARKET` 保留完整分析路径。

### 部署分层

- Primary deploy path is now pull-based V2: `Codex/MCP -> independent ECS Ops API -> ECS local git fetch/checkout -> atomic current symlink switch`.
- The independent Ops API is installed under `/opt/investment-ops` with its own venv and systemd unit. It must not run from `/opt/investment-knowledge/current`, because business releases can be incomplete during deploy failure handling.
- Business releases live under `/opt/investment-knowledge/releases/<sha>`, and `/opt/investment-knowledge/current` points at the active release.
- Full deploy：用于 `Dockerfile`、`requirements.txt`、`docker-compose.prod.yml`、依赖或镜像结构变化；会重建镜像，耗时较长，近期观测约 6 分钟。
- Quick deploy：用于 `investment_knowledge_mcp/`、`scripts/*.py`、`db/`、文档和 shell 脚本等日常迭代；只同步代码并重启 `mcp`、`weekly-review-web`、scheduler 和 bot，不重建镜像，目标耗时 30-120 秒。
- GitHub Actions deploy is secondary/rescue only. The known hosted-runner-to-ECS SSH failure is `ssh: handshake failed ... connection reset by peer` on ECS `:22`; daily releases should not block on that path.
- 生产容器通过 volume 挂载宿主机代码目录，镜像主要承载 Python 依赖和运行环境。

### 发布系统状态

- `/ops/deploy` is asynchronous and returns `deploy_event_id`; status is available through `/ops/deploy-status?id=...` and system overview even if the active business directory is broken.
- `deploy_events` records started/succeeded/failed with commit, mode, duration, health, and logs tail metadata.
- Host-side Ops API/database tools use `POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=55432`; Docker services continue to use `POSTGRES_HOST=postgres POSTGRES_PORT=5432`.
- 发布健康检查需要同时覆盖宿主侧 DB、容器内 DB、`weekly-review-web /health`、`/api/weekly-review` 只读生成，以及前端静态代码版本探测。
- 2026-06-16 周复盘修复已经在云端业务入口验证：`地平线机器人-W HK.09660` 和 `美团-W HK.03690` 这类清仓割肉会归入炸裂/负面信号，不再作为高光或主线贡献；验证命令保存了 `review_reports #4`。
- 同次发布中，云端业务代码已验证正确，`weekly-review-web` 容器内部也已启动；但从公网访问 `http://47.84.190.191:8010/weekly-review` 仍不可达。后续继续处理时应把剩余问题归类为公网入口/网络层排查，而不是周复盘业务逻辑问题。

## 当前推荐下一步

优先顺序建议：

1. 优先做业务功能，不再继续扩展 legacy gateway 架构线。
2. 继续完善收益复盘：基于已保存的 `account_snapshots`，逐步把 `本月收益` 从估算展示升级为“期初/期末净资产 + 出入金/换汇调整 + 区间收益率”的月度复盘口径。
3. 增加每日自动账户快照任务，避免只在手动查询 `本月收益` 时才记录数据。
4. 做持仓知识初始化：优先覆盖前十大持仓的股票画像和板块归属，但不要自动生成正式用户心得。
