# Current Engineering State

## Current Positioning

InvestmentKnowledge MCP is the first backend skeleton of an investment knowledge graph system. It is not an automatic trading system. Its purpose is to preserve stock research, sector classification, factual knowledge, user insights, and later reviews in a searchable, confirmable, and traceable knowledge base.

The personal Mac is the development environment and interactive entrypoint, not the long-running production environment. The long-term runtime target is Alibaba Cloud ECS or another cloud host.

### Database And MCP

- The system uses PostgreSQL plus pgvector.
- The local development database runs through Docker Compose.
- The host port is `55432` to avoid conflict with ReportSystem's PostgreSQL on `5432`.
- The MCP server uses Python and FastMCP.
- Local default transport is `stdio`; cloud transport is `streamable-http`.

### Stock Research Pipeline

The current research pipeline can run end to end:

```text
source material
  -> draft skeleton
  -> model prompt
  -> enriched draft
  -> JSON and source-reference validation
  -> human review artifact
  -> user confirmation
  -> confirmed import
```

Supported providers and checks:

- Manual source-material provider.
- Public web fetch provider.
- OpenAI Responses API provider.
- Mock provider for cost-free pipeline checks.
- Draft validator.
- Human review artifact generator.

### Analysis Context And User Memory

The first analysis-context layer is implemented:

```text
stock/sector
  -> stock profile and sector path
  -> factual knowledge and sources
  -> stock insights
  -> sector insights
  -> portfolio/strategy-level user preferences
  -> pending candidate insights
  -> Markdown analysis context
```

Supported capabilities:

- `get_stock_context`: build stock analysis context.
- `get_sector_context`: build sector analysis context.
- `record_user_insight`: write user insights by stock symbol, sector path, portfolio, or strategy scope.
- `propose_candidate_insight`: write system-inferred candidate insights pending confirmation.
- `confirm_candidate_insight` / `reject_candidate_insight`: promote or reject candidate insights.
- `scripts/build_analysis_context.py`: export readable Markdown context.
- OpenAI analysis provider: when `OPENAI_API_KEY` is configured, analysis commands prefer context-grounded OpenAI output; if unavailable or failed, the system falls back to a local template.

The unified command entrypoint is implemented:

```bash
python scripts/ikg.py "分析一下腾讯"
python scripts/ikg.py "查看候选心得"

python scripts/ikg.py "拒绝候选心得 5"

python scripts/ikg.py "提出个股候选心得 000660 KR 这里写系统推断出的候选心得"
```

`investment_knowledge_mcp.command_router` is the reusable command parsing layer for DingTalk bot, Web API, Hermes/OpenClaw shell, and other entrypoints. It supports:

- Strict commands such as `分析 000660 KR`.
- Natural-language Chinese-style questions such as `怎么看海力士`.
- Stock-name resolution for stored securities, for example `海力士` -> `000660 KR`.
- Short analysis responses while continuing to generate Markdown analysis context files.
- Tiered stock display: `分析 SYMBOL MARKET` returns the Level 1 decision card, while `分析详情 SYMBOL MARKET` keeps the full analysis path.

### Message Entrypoints

### Deployment Tiers

- Default Codex deployment is cloud pull deploy: push the task commit, then call MCP `cloud_deploy(ref=<commit_sha>, mode="quick"|"full")`, which invokes ECS Ops API `/ops/deploy`.
- GitHub Actions is reserved for formal releases, full rebuild backup, and disaster recovery unless explicitly requested.
- Low-risk "deploy validation after changes" requests are standing authorization for task-scoped commit, push, `/ops/deploy`, and remote validation without another conversational approval.
- Full deploy: for `Dockerfile`, `requirements.txt`, `docker-compose.prod.yml`, dependency, or image-structure changes. It rebuilds and uploads the image and is slower.
- Quick deploy: for daily iterations touching `investment_knowledge_mcp/`, `scripts/*.py`, `db/`, docs, or shell scripts. It syncs code and restarts `dingtalk-stream-bot` without rebuilding the image.
- Production containers mount host code by volume. The image mainly carries Python dependencies and runtime environment.

### Cloud Diagnostics And Codex App Integration

- Singapore ECS runs InvestmentKnowledge MCP at `/mcp`.
- Codex App can call Ops tools through the cloud MCP to inspect cloud status and logs.
- Recommended primary ops path: `Codex App -> InvestmentKnowledge MCP /mcp -> ECS internal Ops API`.
- Hermes is currently optional and not a primary runtime dependency.

## Recommended Next Steps

2. Improve return review: use saved `account_snapshots` to upgrade `本月收益` from an estimated view to a monthly return methodology based on beginning/end net assets plus cash-flow and FX adjustments.
3. Add a daily automatic account snapshot task so data is not recorded only when `本月收益` is manually queried.
4. Initialize holding knowledge, prioritizing stock profiles and sector classification for the top holdings, without automatically creating formal user insights.
5. Improve portfolio review UX by grouping risk and attention cost by currency, theme, and holding group instead of naively aggregating across currencies.
6. Security TODO: protect `/mcp`, or split out a read-only Ops MCP entrypoint.
