# 富途持仓接入

目标：用户在钉钉询问 `我的持仓` 时，云端系统实时读取富途持仓并回复。第一版只读，不下单，不解锁交易。

## 推荐架构

```text
钉钉群
  -> dingtalk-stream-bot
  -> command_router
  -> FutuPositionProvider
  -> ECS 本机代理:11112
  -> ECS 本机 OpenD:127.0.0.1:11111
  -> 富途服务器
```

OpenD 跑在 ECS 宿主机上，并监听 `127.0.0.1:11111`。InvestmentKnowledge 容器通过宿主机上的本机代理 `host.docker.internal:11112` 访问 OpenD。这样 OpenD 看到的是来自宿主机本机的连接，避免触发富途 OpenD 的跨网交易连接加密限制。

Compose 已配置 `host-gateway` 映射。安全组不要开放 `11111` 或 `11112`。

## 当前能力

- 新增查询指令：
  - `我的持仓`
  - `我的仓位`
  - `当前持仓`
  - `当前仓位`
  - `持仓`
  - `仓位`
- 使用 `futu-api` 调用 `position_list_query()`。
- 默认 20 秒短缓存，避免钉钉反复询问时触发富途查询频率限制。
- 当前不写入 `positions` 表，只返回实时查询结果。

## 配置项

```text
FUTU_OPEND_HOST=host.docker.internal
FUTU_OPEND_PORT=11112
FUTU_SECURITY_FIRM=FUTUSECURITIES
FUTU_TRADE_MARKET=HK
FUTU_TRADE_ENV=REAL
FUTU_ACCOUNT_ID=0
FUTU_ACCOUNT_INDEX=0
FUTU_POSITION_CACHE_SECONDS=20
FUTU_POSITION_REFRESH_CACHE=true
```

建议优先配置 `FUTU_ACCOUNT_ID`。如果账号只有一个，也可以先用 `FUTU_ACCOUNT_INDEX=0`。

## ECS 准备

1. 在 ECS 上安装并启动富途 OpenD。
2. 登录富途账号，完成设备验证。
3. 确认 OpenD 监听 `127.0.0.1:11111`。
4. 在宿主机上启动 `socat` 代理，把 Docker bridge 可访问的 `11112` 转发到 `127.0.0.1:11111`。

推荐使用仓库里的脚本：

```bash
cd /opt/investment-knowledge
bash scripts/setup_futu_opend_proxy.sh
```

如果脚本提示 OpenD 正在监听 `0.0.0.0:11111`，先停止 OpenD，并用 `-api_ip=127.0.0.1` 重新启动。否则富途会继续把交易连接判定为跨网连接。

如果已经有旧代理，需要重启代理：

```bash
cd /opt/investment-knowledge
bash scripts/setup_futu_opend_proxy.sh --restart
```

脚本等价于手工执行：

```bash
yum install -y socat
DOCKER_HOST_IP=$(ip -4 addr show docker0 | awk '/inet / {print $2}' | cut -d/ -f1)
nohup socat TCP-LISTEN:11112,bind=${DOCKER_HOST_IP},fork,reuseaddr TCP:127.0.0.1:11111 \
  > /opt/futu-opend/socat.log 2>&1 &
```

5. 重启 `dingtalk-stream-bot` 后，在钉钉问：

```text
@机器人 我的持仓
```

## 安全边界

- 第一版只读持仓。
- 不调用 `unlock_trade()`。
- 不保存交易密码，也不保存富途登录明文密码；OpenD 常驻模式会保存 root-only 的 `login_pwd_md5`。
- 不实现下单、改单、撤单。
- 钉钉写入知识库仍受 `DINGTALK_STREAM_ALLOW_WRITE` 和 sender 白名单控制。

## OpenD 常驻服务

临时命令行启动会把登录信息暴露在 `ps -ef` 和 shell history 里。持仓链路跑通后，建议改为 systemd 常驻：

```bash
cd /opt/investment-knowledge
bash scripts/install_futu_opend_systemd.sh \
  --opend-dir /opt/futu-opend/Futu_OpenD_10.6.6608_Centos7/Futu_OpenD_10.6.6608_Centos7
```

脚本会做几件事：

- 交互式读取富途账号和密码，不接受明文密码命令行参数。
- 生成 root-only 的 `/etc/futu-opend/FutuOpenD.xml`，写入 `login_pwd_md5`，并清空 `login_pwd`。
- 检查 `Appdata.dat` 是否存在；如果 OpenD 目录缺失，会尝试从 `/opt/futu-opend` 下自动查找并复制。若找不到但 root 已有 OpenD 运行缓存 `~/.com.futunn.FutuOpenD/F3CNN`，脚本会继续执行。
- 安装 `futu-opend.service`，用 `-cfg_file=/etc/futu-opend/FutuOpenD.xml` 启动 OpenD。
- 安装 `/usr/local/bin/futu-opend-proxy.sh` 和 `futu-opend-proxy.service`，常驻维护 `docker0:11112 -> 127.0.0.1:11111` 代理。
- 停止旧的命令行 OpenD 和旧的 `socat` 代理，然后启用两个 systemd 服务。

安装后检查：

```bash
systemctl status futu-opend.service --no-pager
systemctl status futu-opend-proxy.service --no-pager
ss -lntp | grep -E '11111|11112'
ps -ef | grep FutuOpenD | grep -v grep
```

正确状态应是 OpenD 只监听 `127.0.0.1:11111`，代理监听 Docker bridge 地址的 `11112`，并且 `ps -ef` 里不再出现富途登录密码。
