# 投资知识图谱系统技术方案

## 目标

这个系统的核心不是单纯记录股票数据，而是沉淀一个会随使用增长的投资知识库。第一版重点解决四件事：

1. 个股录入和画像生成。
2. 多级板块树和股票归类。
3. 用户心得、复盘和研究结论的长期记忆。
4. 每日持仓复盘和重要变化提醒。

## 总体架构

```text
用户
  |
  v
投资助手 Agent
  |
  +-- StockResearchAgent: 个股资料收集、画像整理
  +-- SectorResearchAgent: 板块树、产业链、主题逻辑
  +-- PortfolioReviewAgent: 持仓复盘、公告和异动整理
  +-- MemoryAgent: 用户心得结构化、长期记忆写入
  +-- CriticAgent: 来源检查、过期检查、逻辑质疑
  |
  v
InvestmentKnowledge MCP Server
  |
  +-- PostgreSQL: 结构化数据
  +-- pgvector: 语义记忆检索
  +-- Futu MCP: 持仓、行情、交易数据
  +-- 同花顺 MCP: 公告、新闻、板块热度
```

## 数据层选择

第一阶段建议使用：

```text
PostgreSQL + pgvector
```

原因：

- PostgreSQL 适合股票、板块、持仓、交易记录这些强结构化数据。
- pgvector 适合用户心得、研究笔记、公告摘要这类语义检索。
- 图谱关系第一版可以先用关系表表达，后续再迁移到 Neo4j 或 Apache AGE。
- 本地和云端部署都比较简单，迁移成本低。

## 知识类型

系统内的知识建议分成三类，避免所有内容混成一团。

### 事实知识

例如：

- 公司主营业务。
- 股权结构。
- 历史事件。
- 公告摘要。
- 板块归属。
- 产业链位置。

事实知识需要记录来源、时间、置信度、是否被用户确认。

### 用户偏好知识

例如：

- 用户喜欢什么类型的股票。
- 用户如何理解某种股性。
- 用户偏好的交易周期。
- 用户不喜欢哪些风险。

这部分是系统“越用越懂你”的关键。

### 投资复盘知识

例如：

- 某次买入/卖出的原因。
- 判断是否被验证。
- 当时的市场背景。
- 后续认知是否需要更新。

这部分用于让系统逐渐形成“历史判断 -> 结果反馈 -> 认知修正”的闭环。

## 第一版 MVP

第一版不做自动交易，不做全市场扫描，先把知识沉淀闭环跑通。

### 1. 个股录入

流程：

```text
用户输入股票
  -> 大模型查询资料
  -> 生成候选股票画像
  -> 用户确认或修改
  -> MCP Server 入库
```

输出内容：

- 股票基础信息。
- 核心业务。
- 所属板块树。
- 股权结构。
- 股性初判。
- 突出历史。
- 资料来源。

### 2. 板块树

支持多级板块，例如：

```text
AI
  -> 算力
    -> 光模块
      -> 中际旭创
```

一个股票可以属于多个板块，每个关系需要有：

- 关系类型。
- 置信度。
- 来源。
- 是否用户确认。

### 3. 用户心得记忆

用户输入类似：

```text
我觉得这个票股性很妖，适合短线不适合长拿。
```

系统需要沉淀为：

- 目标对象：股票/板块/市场。
- 结构化标签：股性、周期、风险偏好。
- 原始心得文本。
- 向量 embedding。
- 创建时间。

### 4. 每日持仓复盘

流程：

```text
Futu MCP 拉取持仓
  -> 更新持仓表
  -> 同花顺 MCP 拉取公告/新闻/板块近况
  -> 对比历史知识
  -> 生成复盘报告
  -> 重要变化进入待确认知识
```

复盘报告建议包含：

- 今日持仓概览。
- 个股重要事件。
- 相关板块变化。
- 与历史认知冲突的地方。
- 风险提醒。
- 建议继续观察的问题。
- 可入库的新知识。

## 关键原则

1. 大模型不能直接当事实库，只能作为研究员和整理者。
2. 重要知识必须带来源、时间、置信度和确认状态。
3. 用户心得要保留原文，同时提炼结构化标签。
4. 操作记录用事件流保存，不只保存当前仓位。
5. 第一版先完成“录入 -> 查询 -> 复盘 -> 记忆”的闭环。
