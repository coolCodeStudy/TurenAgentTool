# 数据模型设计

## 核心表

### stocks

股票主表。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| symbol | 股票代码 |
| market | 市场，例如 HK、US、A |
| name | 股票名称 |
| core_business | 核心业务 |
| equity_structure | 股权结构 |
| stock_character | 股性 |
| notable_history | 突出历史 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### markets

市场表。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| code | 市场代码 |
| name | 市场名称 |
| total_market_cap | 总市值 |
| category_market_cap | 分类市值，JSON |
| core_companies | 核心公司，JSON |
| updated_at | 更新时间 |

### sectors

板块表，支持父子层级。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| name | 板块名称 |
| parent_id | 父级板块 |
| description | 板块描述 |
| recent_status | 板块近况 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### stock_sector_relations

股票和板块的关系表。一个股票可以属于多个板块。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| stock_id | 股票 ID |
| sector_id | 板块 ID |
| relation_type | 关系类型，例如 main、related、theme |
| confidence | 置信度 |
| source_id | 来源 ID |
| confirmed_by_user | 是否用户确认 |
| created_at | 创建时间 |

### positions

当前持仓快照。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| stock_id | 股票 ID |
| quantity | 持股数量 |
| cost_price | 成本价 |
| market_value | 市值 |
| position_ratio | 仓位比例 |
| source | 数据来源，例如 futu |
| updated_at | 更新时间 |

### trade_events

操作事件流。当前持仓可以由这里推导，也可以同步到 positions。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| stock_id | 股票 ID |
| action_type | buy、sell、increase、reduce、watch、review |
| price | 操作价格 |
| quantity | 数量 |
| reason | 操作原因 |
| source | 来源 |
| happened_at | 发生时间 |
| created_at | 创建时间 |

## 联动逻辑

### 股票录入

插入 stocks 后，系统需要：

1. 检查 market 是否存在，不存在则创建。
2. 检查板块树是否存在，不存在则逐级创建 sectors。
3. 写入 stock_sector_relations。
4. 把来源写入 sources。
5. 把业务、历史、风险等写入 knowledge_items。

### 板块更新

更新 sectors.recent_status 后，系统需要：

1. 找到关联股票。
2. 标记相关股票知识可能需要复核。
3. 在每日复盘中提示板块变化。

### 持仓更新

更新 positions 后，系统需要：

1. 找到持仓股票对应板块。
2. 拉取相关公告和板块近况。
3. 与已有 knowledge_items 和 user_insights 做语义对比。
4. 生成 review_reports。

### 用户心得写入

写入 user_insights 后，系统需要：

1. 保留原始文本。
2. 生成 normalized_summary。
3. 提取 tags。
4. 写入 embedding。
5. 后续分析个股或板块时优先检索相关心得。
