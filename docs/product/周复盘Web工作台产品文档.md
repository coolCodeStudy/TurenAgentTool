# 周复盘 Web 工作台产品文档

> Status note (2026-06-18): This document remains the product reference for the weekly-review workbench shape. The current save/refresh contract is governed by `docs/techplans/weekly-review-week-scope-force-refresh.md`: one report row per natural week, read existing content by default, generate only when missing, and `Force refresh` overwrites the same weekly report after confirmation. Older wording about draft/finalized separation should be treated as historical terminology unless it matches that current contract.

## 1. 背景判断

钉钉这条线适合做通知、轻量命令和异步提醒，但不适合承载完整投资复盘。

原因很直接：

- 周复盘不是一句命令，它需要看表格、看缺口、看历史、确认候选心得。
- 钉钉消息流天然线性，复杂内容会被折叠、截断、刷走。
- 一旦接入交易记录、持仓快照、指数、舆情、新股、知识库，用户需要的是一个可停留、可修改、可确认的工作台。
- 钉钉可以保留为提醒入口，但不应该是第一产品界面。

因此第一阶段产品形态建议从钉钉转向 Web。

## 2. 产品定位

产品名暂定：InvestmentKnowledge Web 工作台。

一句话定位：

> 一个围绕真实交易、真实持仓和个人投资记忆构建的投资复盘工作台。

第一款产品：

> 周复盘。

后续产品围绕周复盘自然长出来，包括持仓工作台、交易复盘、研究队列、心得确认、历史验证、投资日历。

## 3. 产品原则

### 3.0 Weekly Reviews Are Generated By Week

Weekly review is not an arbitrary date-range query tool. Future versions must generate and read reviews by fixed natural week. The same week should be generated once by default; reopening that week should read the existing draft or finalized report. If the user wants to refetch trades, indexes, macro events, news, and opportunity lists, they must explicitly click `Force refresh`. See [PRD-weekly-review-week-scope-and-force-refresh](PRD-weekly-review-week-scope-and-force-refresh.md).

### 3.1 先事实，后解释

页面先展示真实交易、真实持仓、真实快照，再让模型总结。

高光、炸裂、当前持仓分析必须来自数据，不允许模型空写。

### 3.2 缺数据要明说

指数、雪球、Twitter/X、公告、财报等外部数据如果没有接入，页面必须显示缺口。

不能为了让报告完整而脑补市场故事。

### 3.3 复盘不是资讯流

产品不做无限新闻流，不做每日信息轰炸。

周复盘只回答：

- 本周发生了什么。
- 我赚在哪、亏在哪。
- 当前仓位哪里危险。
- 下周要盯什么。
- 哪些心得值得沉淀。

### 3.4 用户确认才进入记忆

模型可以生成候选心得，但不能直接写入正式用户心得。

网页上必须有“确认 / 拒绝 / 稍后看”的明确操作。

### 3.5 周复盘是主入口

第一阶段不要把产品做散。

其他模块可以露出入口，但主体验必须围绕“每周完成一次高质量复盘”展开。

## 4. 信息架构

Web 工作台建议分为 6 个一级产品。

| 产品 | 作用 | 第一阶段状态 |
| --- | --- | --- |
| 周复盘 | 每周生成正式复盘报告 | P0 核心 |
| 持仓工作台 | 看当前持仓、主题暴露、风险和处理队列 | P1 |
| 交易复盘 | 看区间成交、赚钱亏钱交易、执行问题 | P1 |
| 研究队列 | 管理个股研究任务和审计状态 | P2 |
| 心得确认 | 确认/拒绝候选心得，维护个人记忆 | P1 |
| 历史验证 | 回看过去判断是否被验证/证伪 | P2 |

第一版左侧导航：

```text
InvestmentKnowledge

- 本周复盘
- 当前持仓
- 交易复盘
- 心得确认
- 研究队列
- 历史复盘
- 数据源状态
```

第一版真正做深的是“本周复盘”。

## 5. 周复盘产品目标

### 5.1 用户目标

用户每周打开页面，能在 10 分钟内完成：

- 看清本周赚钱和亏钱的来源。
- 看清组合现在最需要处理的风险。
- 看清下周要盯的新股、事件、财报和持仓动作。
- 确认少数真正值得沉淀的心得。
- 生成一份可回看的复盘报告。

### 5.2 产品目标

周复盘页面要从数据自动生成 80% 内容，用户补充最后 20% 主观判断。

系统负责：

- 拉交易记录。
- 拉账户/持仓快照。
- 拉当前持仓。
- 拉新股日历。
- 拉知识库和心得。
- 标出数据缺口。
- 生成结构化复盘草稿。

用户负责：

- 判断故事是否成立。
- 修改下周展望。
- 确认候选心得。
- 决定是否保存正式报告。

## 6. 周复盘页面结构

### 6.1 顶部区域

页面顶部展示：

| 元素 | 说明 |
| --- | --- |
| Review week | Defaults to the current natural week; can switch to previous/current/historical weeks |
| 生成状态 | 未生成 / 生成中 / 已生成 / 数据不完整 |
| 数据新鲜度 | 交易记录、持仓、账户快照、新股、指数、外部事件 |
| Primary actions | Generate weekly review, Force refresh, Save finalized report |

数据状态条示例：

```text
交易记录：已读取 93 笔
持仓快照：已读取 30 个持仓
账户快照：今日已读取，周初快照缺失
港股新股：已读取 5 个
指数：未接入
外部事件：未接入
```

这条状态非常关键，它能减少用户对报告准确性的误判。

### 6.2 复盘目录

周复盘固定 6 个模块：

```text
1. 高光时刻
2. 炸裂时刻
3. 指数
4. 整体故事
5. 下周展望
6. 当前持仓分析
```

右侧可以做锚点导航，让用户快速跳转。

## 7. 模块设计

### 7.1 高光时刻

用户语言定义：

> 本周赚钱比较多的交易。

产品定义：

高光时刻是本周实际贡献收益最多、或者执行质量最好的交易/持仓变化。

数据优先级：

1. 本周已实现盈利交易。
2. 本周持仓浮盈变化。
3. 当前持仓累计浮盈。

如果只有当前持仓累计浮盈，页面必须标注：

```text
这是当前累计盈亏，不一定是本周新增收益。
```

展示方式：

| 标的 | 类型 | 金额 | 发生了什么 | 复盘问题 |
| --- | --- | ---: | --- | --- |
| HK.02476 胜宏科技 | 当前浮盈 | +6680 HKD | 当前持仓贡献明显 | 是产业判断正确，还是短期情绪溢价 |
| HK.07709 南方两倍做多海力士 | 当前浮盈 | +2800 HKD | AI memory 方向强势 | 杠杆产品有没有退出纪律 |
| US.RKLB Rocket Lab | 累计收益 | +1001 USD | 仍是美股侧重要正贡献 | 继续持有的条件是什么 |

用户操作：

- 标记为“值得复盘”。
- 写一句自己的解释。
- 生成候选心得。

### 7.2 炸裂时刻

用户语言定义：

> 本周亏钱比较多的交易。

产品定义：

炸裂时刻是本周实际亏损最大、或者最需要反思的交易/持仓变化。

数据优先级：

1. 本周已实现亏损交易。
2. 本周持仓浮亏扩大。
3. 当前持仓累计亏损。

展示方式：

| 标的 | 类型 | 金额 | 可能问题 | 下周处理 |
| --- | --- | ---: | --- | --- |
| HK.09988 阿里巴巴-W | 历史拖累 | -9700 HKD | 旧仓占用注意力和资金 | 重新判断是否仍有配置理由 |
| HK.01810 小米集团-W | 历史拖累 | -5900 HKD | 亏损较深，容易变成沉没成本 | 单独复盘基本面和仓位意义 |
| US.SY 新氧 | 历史拖累 | -810 USD | 非主线低效仓位 | 进入处理清单 |

页面要避免用温和文案糊弄。

亏钱的地方要直接、清楚、可处理。

### 7.3 指数

用户语言定义：

> 主要看美股、A股、港股。

产品定义：

指数模块用于解释本周市场环境，而不是写宏观散文。

指数篮子：

| 市场 | 指数 |
| --- | --- |
| 美股 | Nasdaq 100、S&P 500、SOX 半导体、Russell 2000 |
| 港股 | 恒生指数、恒生科技、国企指数 |
| A股 | 沪深300、创业板指、科创50、半导体/通信相关指数 |

展示方式：

| 市场 | 指数 | 本周涨跌 | 最大单日波动 | 对组合含义 |
| --- | --- | ---: | --- | --- |
| 美股 | SOX 半导体 | 待接入 | 待接入 | 影响 MU、MRVL、AVGO、LITE、DRAM |
| 港股 | 恒生科技 | 待接入 | 待接入 | 影响阿里、小米、科技成长仓 |
| A股 | 科创50 | 待接入 | 待接入 | 影响半导体和硬科技情绪 |

第一版如果指数数据未接入，就显示“待接入”，不要让模型补。

### 7.4 整体故事

这是周复盘里最难、也最有产品价值的一块。

不能简单做成“AI 写一段市场总结”。

它应该分成三层。

#### 第一层：事实拼图

来自系统可验证数据：

- 本周交易最活跃标的。
- 本周买入/卖出最多的方向。
- 当前持仓正贡献和负贡献。
- 新股日历。
- 指数涨跌。
- 外部事件。

页面先列事实：

```text
本周交易活跃：07709、09995、03690、SPCE、WKK
当前强势贡献：胜宏科技、DRAM、APP、MU、RKLB
当前主要拖累：阿里、小米、巨子、新氧、TMDX
新股事件：溜溜梅上市，海清智元/星源材质/华健未来-B 可申购
指数数据：待接入
外部事件：待接入
```

#### 第二层：故事候选

模型基于事实拼图生成 2-3 个故事候选，而不是唯一结论。

示例：

```text
故事候选 A：AI memory / AI 基础设施仍是组合主线
- 支持证据：07709、DRAM、MU、MRVL、LITE、胜宏科技在组合中占据重要位置
- 风险：主题拥挤、杠杆产品路径依赖、业绩兑现压力

故事候选 B：旧港股成长仓继续消耗组合注意力
- 支持证据：阿里、小米、巨子仍是港股侧主要拖累
- 风险：如果不处理，周复盘会长期被旧亏损仓牵制
```

#### 第三层：用户选择

用户可以选择：

- 采用这个故事。
- 修改故事。
- 标记为不成立。
- 生成候选心得。

这一步很重要，因为“整体故事”其实是用户投资框架的一部分，不能完全交给模型。

### 7.5 下周展望

用户语言定义：

> 看有什么新股上市，看要做什么。

产品定义：

下周展望不是预测涨跌，而是生成下周需要处理的工作清单。

输入：

- 港股新股和上市日。
- 当前持仓盈利/亏损前列。
- 本周交易活跃标的。
- 主题拥挤程度。
- 候选心得。
- 外部事件和财报日历。

展示方式：

| 类型 | 事项 | 为什么重要 | 需要决定 |
| --- | --- | --- | --- |
| 新股 | 溜溜梅上市 | 已截止待上市，需要观察首日表现 | 否 |
| 新股 | 海清智元可申购 | 下周仍在申购窗口 | 是 |
| 主题 | AI memory/HBM | 影响 07709、DRAM、MU | 是 |
| 仓位 | 旧港股成长仓 | 阿里、小米、巨子仍是主要拖累 | 是 |
| 风险 | 杠杆产品 07709 | 产品机制不适合无纪律持有 | 是 |

用户操作：

- 加入“下周待办”。
- 标记“不重要”。
- 写自己的判断。
- 下周复盘时自动回看是否执行。

### 7.6 当前持仓分析

用户语言定义：

> 结合我的持仓和知识库做一个 table。

产品定义：

这是周复盘的核心表格，不写成大段分析。

字段：

| 字段 | 说明 |
| --- | --- |
| 市场 | US / HK / CN |
| 标的 | 股票代码 + 名称 |
| 主题 | 来自知识库或规则映射 |
| 市值 | 原币种 |
| 盈亏 | `pl_val` + `pl_ratio` |
| 状态 | 强势贡献 / 历史拖累 / 核心观察 / 高波动 / 待处理 / 补研究 |
| 知识库观点 | 一句话 |
| 下周节奏 | 拿住、观察、补研究、减仓候选、等待事件 |

表格需要支持：

- 按市场筛选。
- 按主题筛选。
- 按盈亏排序。
- 只看“待处理”。
- 只看“补研究”。

第一版可以不做复杂交互，但字段必须一次设计好。

## 8. 页面交互流程

### 8.1 首次打开

用户进入“本周复盘”页面。

页面展示：

- 本周日期范围。
- 数据源状态。
- “生成本周复盘”按钮。
- 如果上次已有草稿，展示草稿。

### 8.2 生成复盘

点击“生成本周复盘”后：

1. 拉本周交易记录。
2. 拉当前持仓。
3. 拉账户快照。
4. 拉新股日历。
5. 拉知识库和心得。
6. 尝试拉指数和外部事件。
7. 生成 6 个模块。

生成完成后，页面不是直接保存正式报告，而是进入“草稿态”。

### 8.3 用户编辑

用户可以编辑：

- 整体故事。
- 下周展望。
- 每个高光/炸裂的复盘解释。
- 候选心得。

交易、持仓、盈亏这些事实字段不允许直接编辑，只能刷新数据。

### 8.4 保存正式复盘

用户点击“保存正式复盘”后：

- 保存 Markdown 报告。
- 保存结构化 JSON。
- 生成候选心得。
- 记录本周下周展望，供下周回看。

### 8.5 确认候选心得

保存后跳出候选心得区：

```text
本周提炼出 3 条候选心得：

[确认] [拒绝] [稍后]
```

确认后才进入正式记忆。

## 9. 状态设计

### 9.1 数据完整

页面正常生成完整复盘。

### 9.2 部分数据缺失

常见缺口：

- 周初账户快照缺失。
- 指数行情未接入。
- 外部事件未接入。
- 交易成本口径不足，无法计算严格已实现盈亏。

页面必须显示：

```text
本报告为部分数据版本。
以下模块可信度较低：高光/炸裂的本周归因、整体故事。
```

### 9.3 富途连接失败

页面显示：

- 失败原因。
- 上次成功数据时间。
- 可用的历史快照。
- 不要空白。

### 9.4 生成失败

页面保留已成功拉取的数据。

例如交易记录成功、外部故事失败，那就展示交易和持仓，故事模块显示失败。

## 11. 后续产品设计

### 11.1 当前持仓

作用：

日常查看组合结构，不等到周末。

核心问题：

- 我现在持仓最大的风险是什么？
- 哪些是主线仓，哪些是试错仓？
- 哪些仓位只是在消耗注意力？
- 哪些持仓缺研究？

页面模块：

- 按市场分组。
- 按主题分组。
- 盈亏贡献。
- 待处理清单。
- 补研究清单。

### 11.2 交易复盘

作用：

专门复盘执行质量。

核心问题：

- 本周交易最多的是什么？
- 哪些交易赚钱，哪些亏钱？
- 有没有冲动交易、频繁交易、追高杀跌？
- 买入理由和卖出结果是否一致？

页面模块：

- 成交日历。
- 标的成交汇总。
- 已实现盈亏。
- 高频交易提醒。
- 执行问题标签。

### 11.3 心得确认

作用：

维护个人投资记忆。

核心问题：

- 哪些候选心得真的是我的观点？
- 哪些只是模型误读？
- 哪些观点已经过时？

页面模块：

- 待确认。
- 已确认。
- 已拒绝。
- 按股票/板块/组合/策略筛选。

### 11.4 研究队列

作用：

把持仓里“缺研究”的部分变成任务队列。

核心问题：

- 哪些持仓没有知识库？
- 哪些研究草稿需要审核？
- 哪些股票最近需要更新？

页面模块：

- 当前研究任务。
- 待审核草稿。
- 按持仓优先级排序。
- 数据新鲜度。

### 11.5 历史验证

作用：

让系统真正帮助用户进步。

核心问题：

- 我上周说要关注什么，这周发生了吗？
- 我之前的判断被验证还是被打脸？
- 同样的错误是否重复出现？

页面模块：

- 上周展望回看。
- 历史心得验证。
- 重复错误统计。
- 投资风格变化。

## 12. 成功指标

### 北极星指标

每周完成一次正式周复盘。

### 输入指标

- 每周成功读取交易记录次数。
- 每周成功读取持仓快照次数。
- 每周生成候选心得数量。
- 每周确认/拒绝候选心得数量。
- 每周保存正式报告次数。

### 质量指标

- 高光/炸裂是否来自真实数据。
- 当前持仓 table 是否覆盖全部持仓。
- 下周展望是否能在下周被回看。
- 用户是否愿意修改并保存报告。
- 外部故事是否有清楚来源。

## 13. 第一版验收标准

- 用户打开 Web 后，第一屏就是“本周复盘”，不是产品介绍页。
- 页面能展示 6 个固定模块。
- 页面能明确显示哪些数据已接入、哪些未接入。
- 高光/炸裂不能是模型空话。
- 当前持仓分析必须是 table。
- 下周展望必须包含新股和持仓处理事项。
- 整体故事必须区分事实、故事候选、用户确认。
- 保存前是草稿，保存后才成为正式复盘。
- 候选心得必须等待用户确认。

## 14. 当前决策

建议当前产品方向：

1. 放弃把钉钉作为主产品界面。
2. 钉钉保留为通知入口，例如“本周复盘已生成，点击 Web 查看”。
3. 第一版 Web 只做周复盘，不急着做完整投资系统。
4. 周复盘页面必须围绕真实交易和持仓，不做空泛 AI 报告。
5. 其他产品先作为导航入口和后续路线，不在第一版抢资源。
